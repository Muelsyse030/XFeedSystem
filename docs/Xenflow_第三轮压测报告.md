## 五、本轮结论与下一步

1. **CPU 问题已终结**：`diverseRank` 82.86% → 不在热点。当前瓶颈是 I/O（syscall 20%+）和 GC（13%）。
2. **200+ 并发错误的根源是写路径**：评论/点赞/收藏都在事务里 `UPDATE notes SET counter+1`，高并发下行锁排队、连接池逼近上限。**下一步最大收益是计数器解耦**：互动事务只插记录 + 事件，计数由 worker 异步累加（Redis INCR + 定时落库），能同时解决行锁和 MySQL 连接压力。
3. **powf 微优化**：Diversity 里每个候选按话题数调用 `powf`，可以预计算"话题出现次数 → 惩罚幂"表，省掉循环内乘方（预估省 2-5% CPU）。
4. **搜索是唯一慢读接口**（2,009 QPS / p99 42ms，Meili 依赖），高频关键词加 10-30s 结果缓存可数倍提升。
5. **数据卫生**：发帖接口在压测中会大量造数据（20s ≈ 4.5 万条）。第三轮测试产生的 6.2 万条已备份到 `notes_backup_r3` 表并清理，当前库保持 612 条原始数据。
